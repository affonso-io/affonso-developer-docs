---
title: "Apply to Campaign"
api: "POST https://api.affonso.io/v1/program/campaigns/{id}/applications"
description: "Submit a campaign application on behalf of one of your affiliates"
---

Submit an application for an affiliate on your team. The affiliate must be an approved partner of the campaign's program. Requires `write:affiliates`.

The same operation is available through the [`affonso_apply_to_campaign`](/mcp/tools/campaigns) MCP tool.

## Path Parameters

<ParamField path="id" type="string" required>
  Encoded campaign id
</ParamField>

## Body Parameters

Unknown body fields are rejected.

<ParamField body="affiliate_id" type="string" required>
  Id of an affiliate on your team
</ParamField>

<ParamField body="answers" type="string" required>
  The affiliate's answer to the campaign's `application_prompt`. Trimmed, 1 to 10,000 characters.
</ParamField>

## Response

Returns the created or updated application object (HTTP 201).

<ResponseField name="success" type="boolean">
  Always `true` for successful responses
</ResponseField>

<ResponseField name="data" type="object">
  The application. Fields match the application object in [List Campaign Applications](/api/endpoint/campaigns/list-applications). A new or reset application has `status` `"PENDING"` and `reviewed_at` `null`.
</ResponseField>

<RequestExample>
```bash cURL
curl -X POST "https://api.affonso.io/v1/program/campaigns/<campaign_id>/applications" \
  -H "Authorization: Bearer sk_live_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "affiliate_id": "<affiliate_id>",
    "answers": "<application answers>"
  }'
```
</RequestExample>

## Notes

- Requires `write:affiliates`.
- The campaign must have `application_required` set to `true` and a `status` of `SCHEDULED` or `ACTIVE`. Otherwise the call returns `VALIDATION_ERROR` (HTTP 400).
- The affiliate must belong to your team (`AFFILIATE_NOT_FOUND`, HTTP 404) and be an approved partner of the campaign's program whose affiliate status is not `INACTIVE`, `REJECTED`, or `BANNED` (`FORBIDDEN`, HTTP 403).
- Re-applying overwrites `answers` and resets a `PENDING` or `REJECTED` application to `PENDING`, clearing `reviewed_at`. An `ACCEPTED` application returns `CONFLICT` (HTTP 409).
